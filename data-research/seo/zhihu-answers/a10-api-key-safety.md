# API Key 泄露了怎么办？

先讲个吓人的：朋友有次把带 Key 的截图发进了群里，第二天才反应过来。他第一反应是去翻日志「看看有没有人用」——我让他停手，直接吊销。确认泄露的那一刻，吊销优先于一切调查。泄露出去的 Key 就是别人的钱包，你多调查一分钟，账单就多跑一分钟。

正确动作按顺序就四步。

第一步，立即吊销。进控制台直接作废这把 Key，别「先看看」。重新生成一把新 Key 只要一分钟，损失排查完全可以放到后面做。

第二步，审计调用记录。翻用量曲线和账单：异常时段的调用、你没调过的模型、陌生地区的来源，把泄露的时间窗口划出来，估算损失。就算暂时没发现异常也别掉以轻心，至少再观察几天——我见过隔了一周才开始跑量的。

第三步，换存放方式。Key 会泄露，十有八九是被硬编码进了代码、发进了截图、或者提交进了仓库。新 Key 请进环境变量或密钥管理工具。哦还有，如果它进过 git 仓库，记住是改 Key 而不是删文件——历史提交里它还完整躺着呢。

第四步，最小权限拆分。别再一把 Key 走天下。按项目、按环境拆成子 Key，能设额度上限就设上限，能限模型范围就限范围。这样下次再出事，爆炸半径只有一把小钥匙。

事后加固我也顺手列一下：`.gitignore` 全量检查一遍；启动脚本里的明文 Key 全部转环境变量；前端代码里的 Key 等于公开，必须撤掉；发帖和截图前先扫一眼有没有 Key 残影。

最后纠正一个我见过无数次的误区——「删掉文件重新提交」就算处理完了？不是的。git 历史里旧 Key 一字不差地保留着，唯一正确的处理永远是吊销换新，历史清理只是辅助手段。

对了，轮到你自查了：你的 Key 现在放在哪？已经放进环境变量的，扣个 1。
