# API Key 泄露了怎么办？

先记住一句话：确认泄露的那一刻，吊销优先于一切调查。泄露出去的 Key 就是别人的钱包，你多调查一分钟，账单就多跑一分钟。正确动作按顺序是这四步。

**第一步：立即吊销。**
进控制台直接作废这把 Key，不要「先看看有没有人用」。重新生成一把新 Key 只要一分钟，损失排查完全可以放到吊销之后。

**第二步：审计调用记录。**
翻用量曲线和账单：异常时段的调用、你没调过的模型、陌生地区的来源，划出泄露的时间窗口，估算损失。就算暂时没发现异常也别掉以轻心，至少再观察几天。

**第三步：换掉存放方式。**
Key 之所以泄露，十有八九是因为它被硬编码进了代码、发进了截图、或者提交进了仓库。新 Key 请进环境变量或密钥管理工具；如果它进过 git 仓库，注意是改 Key 而不是删文件——历史提交里它还完整躺着。

**第四步：最小权限拆分。**
别再一把 Key 走天下。按项目、按环境拆成子 Key，能设额度上限就设上限，能限模型范围就限范围。这样下次再出事，爆炸半径只有一把小钥匙。

事后加固清单：`.gitignore` 全量检查一遍；启动脚本里的明文 Key 全部转环境变量；前端代码里的 Key 等于公开，必须撤掉；发帖和截图前先扫一眼有没有 Key 残影。

最后纠正一个常见误区：很多人以为「删掉文件重新提交」就算处理完了——git 历史里旧 Key 一字不差地保留着，唯一正确的处理永远是吊销换新，历史清理只是辅助手段。
