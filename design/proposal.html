一、实测证据：三个硬伤

每一条都有可复现的数值。方法：无头 Chrome 加载真实页面，用 iframe 锁定精确视口宽（绕开 macOS 最小窗口 500px 限制），读取 documentElement.scrollWidth 与 getBoundingClientRect()。

硬伤 1 · 移动端整页横向滚动

P0

≤640px 时 .tabs 有 12 个不可断行按钮，min-content 宽 1108px。它作为 flex item 未重置 min-width，于是把整个 .toolbar 撑到 1108px，.toolbar > span 又因 margin-left:auto 在 column 容器里被推到最右，最终 scrollWidth = 1120 —— 视口只有 390px，右侧 730px 完全在屏幕外。

硬伤 2 · 表头与数据列整体错位 109px

P0

.lhead（表头）与 .row（数据行）都用 96px minmax(0,1fr) 116px max-content，但第 4 列是 max-content：表头里是「操作」二字（24px），数据行里是「⚡ ☆ 领取」按钮组（133px）。中间的 1fr 吸收了 109px 差值，把第 3、4 列整体右推 —— 结果「核验」表头压在状态徽章右边 109px 处，点错列。

六项改动全部已实现并在沙盘实测通过。前两项是修 bug，后四项是主动做的体验升级。

手机首屏平台数 1.5 → 6+，是本次改版体感最强的一处。

详情展开

桌面中栏有 749px，但 .r-value 是 nowrap + ellipsis，80–120 字的额度说明被砍成「…」。现在每行加「详情」按钮，点开是结构化面板：完整额度、领取规则、备注、折算口径、截止时间、核验时间、官方入口。

原来只能靠 title 悬停看全文（手机根本悬停不了）；现在是点击即读，且信息按字段归位而不是一坨。

暗色模式

跟随系统 prefers-color-scheme，也可手动切换并用 localStorage 记忆。深浅两套色板只改 CSS 变量，组件层零改动 —— 对一个程序员向的 AI 工具站，暗色几乎是标配，也是差异化。

已在沙盘渲染验证，深色下对比度与层级均正常，见下方对比图。

顶部入群条降噪

原「扫码进微信群」是全宽琥珀色高对比条，压在 h1 之上，跟「全球羊毛 349 亿」这个核心价值抢黄金位。改为轻量提示条 + 药丸按钮，权重下调但不删转化路径。

首屏第一眼应该落在 「今天能薅多少」，不是「进群领折扣码」。

四、落地与验收

交给 zcode 主会话执行。改版已实现为可直接合并的两份产物，位于同目录。

  1. 1 · 先合纯 CSS 补丁（低风险，10 分钟）

    把 design/patch-v3.css 的内容追加到 index.html 主 <style> 块尾部。这一步单独就修掉硬伤 1 和硬伤 2：

    /* 表头对齐：第 4 列 max-content → 定宽，两处共用同一模板 */
:root{ --cols:96px minmax(0,1fr) 116px 156px; }
.lhead,.row,.skel{ grid-template-columns:var(--cols) }

/* 移动端横向溢出根治 */
@media(max-width:640px){
  .tabs{ min-width:0; max-width:100%; width:100%; overflow-x:auto }
  .toolbar > span{ margin-left:0!important; min-width:0; width:100% }
}
  2. 2 · 再合并 JS/结构改动（需回归）

    design/index-v3.html 是改版后的完整页面（相对原版 +8.9KB，12 处精确替换）。它包含：收益条形图、CTA 分级、目录折叠、详情面板、暗色模式、错误文案修正。也可以只把这几段摘出来合进现有 index.html。

  3. 3 · 按 zcode 的既有纪律验收

    沿用 SESSION_STATE.md 里的规矩：CSS 改动必须截图实测（JSC 语法门抓不到布局问题），跑 360 / 390 / 430 / 768 / 1440 五档，桌面零回归。

  4. 4 · 顺手修掉一个文案 bug

    原 catch 块无论何种失败都提示「file:// 协议无法 fetch」，HTTPS 线上真出故障时会把排查方向带偏。改版会区分本地预览 / 网络异常，并给出「重试」按钮。

协作提示：仓库 index.html 由 zcode 主会话单方写入，本次未改动该文件，也未提交 git —— 避免与主会话产生写冲突。所有产物以独立文件落在 design/ 目录，等 zcode 确认后再合并。
已知取舍：收益条形图用 tokSort（含美元/人民币折算）做比例，与「收益」排序键完全一致，不会出现排序与条长打架；手机端「折扣链接」按钮在 78px 操作列里仍会折成两行，属可接受的次要问题，未在本轮处理。
