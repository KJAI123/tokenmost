# 采集与通知可靠性修复（2026-11-22）

承接 OpenCode `02-tokenmost-repair` v2 候选，逐一核对三份正式源文件与交付清单的 SHA-256 后，在隔离工作树应用补丁。原交付只完成离线候选验收，本次也未执行真实采集、读取真实凭据、发送飞书消息、修改调度器或部署。

采集层按响应头或 gzip/deflate 魔数解压后再提取关键词；不支持的压缩、解压失败及高控制字符载荷标记为 `binary`，不产生关键词证据。无响应头时的二进制识别仍是启发式检查，不能据此确认所有响应均为可读文本。`--only` 结果单独写入 `latest-partial.json` 与 `harvest-<日期>-partial.md`，空结果拒绝落盘。diff 对显式部分、空或无法解析的当前快照拒绝建立/滚动基线，并保留旧版源数骤减保护；正常变更仍生成告警。

通知仅 token 获取阶段允许追加一次重试；HTTP 2xx、业务码成功且含有效 token 才能进入消息阶段。消息 POST 每次调用最多一次。超时、断连、5xx、非法成功体等记为 `unknown`，保存原文和请求标识供人工核对；即使 outbox 落盘失败，也保留退出码 3。默认 outbox 为 `data-research/notify-outbox.md`，加入 Git 忽略列表，避免常规 `git add -A` 收录通知暂存正文。自定义 `--outbox` 路径须由调用方保持私有。

| 退出码 | 含义 | 后续处理 |
| --- | --- | --- |
| 0 | 接口明确成功 | 无需重发 |
| 1 | 确定未送达或 token 瞬时失败且消息未 POST | 查明失败原因，再决定补发 |
| 2 | 参数、配置或 token 明确拒绝 | 修正输入/配置后处理 |
| 3 | 消息结果不确定，可能已送达 | 先人工核对；不得按“非零自动重试”盲目补发 |

请求附带按内容生成的稳定 `uuid`。[飞书发送消息官方文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/create?lang=en-US) 描述其一小时内去重语义；本轮未验收真实账号的服务端效果，不能把该参数当成自动重发或确认到账的依据。

候选验收后补充了 token 非 2xx 回包仍带成功字段、显式部分快照超过源数阈值、解压失败、outbox 落盘失败等边界。保留原业务数据，不根据任务索引的 error 推断凭据故障。仓库内未发现通知工具的外部 Python 导入调用；通知调度包装层未在本次审查范围中，启用前应核对其退出码处理。现有采集工作流和容器脚本会吞掉部分非零返回，本轮未修改它们。
