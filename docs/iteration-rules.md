# TokenMost 网站迭代规则

**目标：让用户找到可领取的权益，看清额度、领取条件和可信来源。** 采集记录、公开权益和核验是三件事，分别记录。

## 1. 每轮先查缺口

- 跑 `python3 tools/source_audit.py` 留下基线。按「已有稳定信源但未成条」「已上架但待复核」「已有条目但缺少独立证据」依次处理。优先覆盖常设免费 API、每日或每月刷新、即将截止的活动和用户点名的平台。
- 待看线索从 `data-research/discovery-queue.md`、`source_candidates.json`、公众号/RSS 产出和 `review-queue.md` 取。新平台先查 `deals.json`、`sites.json`、`tools/harvest_sources.json` 与 `tools/sources.json`，确认缺的是采集、公开目录、具体权益，还是仅缺证据。
- 每日先处理活动截止、页面变更和高频失联；每周检查各类别是否只依赖单一聚合站，从候选库复核一批高价值缺口。同一域可以有不同产品，但一个 URL 返回 200 不代表内容有效。采集遵守站点规则；遇登录墙、地区限制或页壳，记录所欠证据。

## 2. 用证据决定如何收录

| 证据 | 去向 | 上架条件 |
|---|---|---|
| 官方定价、活动条款、公开文档、可复现的结构化接口 | `deals.json` + `tools/sources.json` | 原文能支持文案中的额度、适用对象与计费条件。 |
| 可复现的实测、公开到账记录 | 佐证，附平台官方入口 | 区分官方条款与实测，注明日期、地区和账号条件；单次结果不能推广成普遍规则。 |
| 公众号、社区、聚合目录或旧快照 | `harvest_sources.json` 或发现队列 | 用于发现；暂无法核实时保持草稿或待复核状态，不写成已核验。 |
| 只剩历史促销、过期、证据矛盾、重复 | 保留处理记录 | 活动过期标 `expired`；信息被证伪或合并时归档并注明理由。 |

每个新公开条目写明：提供方与产品、额度原单位、刷新周期、是否需注册/绑卡/付费/审核、地区与适用对象、截止时间（含时区如有）、公开入口和核验日期。能确认到什么程度就写到什么程度。没有官方比例及依据时，不用 Neurons、积分、次数、CPU/GPU 小时或钱数硬算 Token；每日/每月刷新用 `cadence` 表达，同一权益不因多一条信源而加进总额两次。英文页面的新条目补 `value_en`、`rule_en` 与需要的 `notes_en`。

`url` 是用户的操作入口；`sources` 是证据数组，每项至少 `url` 与 `title`，新条目再标 `kind`（`official` / `firsthand` / `community` / `aggregator`）。可用的补充链接全部留在原条目；同一权益按平台、产品、领取门槛、额度和周期核对后合并，共享同一 `id`，不要按域名粗暴去重。合并时在旧条目保留证据和指向，并把独有证据并入主条目。URL 失效或被替换时，保留原来源作为历史证据，并补上新 URL 和处理说明。

## 3. 采集、核验与同步

- `tools/harvest_sources.json` 发现增量，`tools/sources.json` 监控已知权益，`sites.json` 提供平台入口。一个来源已存在就更新关键词或绑定，不再造重复采集任务。每个采集登记使用独立 ID；工具从 URL 生成 ID，不能只取 docs、console 等常见子域名。
- 新增官方页面监控默认使用 `auto_verify: false`。哈希一致表示页面未检测到变化，不代表到账实测，也不更新人工核验时间；发生持续变更则进复核。已有自动续期规则，逐条确认来源能证实权益再保留。监控无法直接证实付费状态或到账时，禁止跨过人工复核。
- 同步只修改负责的字段。手工维护的 `sources`、领取规则和地区/到账限制按条目 ID 合并；不能用旧快照或空数组覆盖。自动同步在写回前检查已有证据链接是否丢失，拦下回归并输出条目 ID。GitHub Pages 的推送发布也与推送前的版本比较；独立采集任务写入前同样跑基线对比。
- 发布前用 `git show HEAD:deals.json > /tmp/tokenmost-before.json` 取基线，再跑 `python3 tools/source_audit.py --against /tmp/tokenmost-before.json` 和 `python3 tools/check.py`。检查新增条目、归档原因、RSS/平台页/搜索入口变化；区分「已核验」「待复核」「监控中」。线上发布前只合入目标变更，先确认最新自动同步和可回滚版本。

## 4. UI 验收与记录

- 每轮选一个明确问题（如找不到某平台或不清楚领取门槛），记下当前完成路径，再比较改版后的点击数、步骤和失败点。
- 首页保持列表紧凑。摘要默认可见；聚合和单条都必须能打开原始信源。领取按钮和复制行为不变，门槛和过期状态不能藏进详情。
- 中英文首页分别验证手机（至少 320px 和常用手机尺寸）、平板和桌面：无横向溢出；搜索、空状态重置、筛选、排序、分页、信源展开、核验日期和总账可用。键盘能访问主要入口，焦点可见；不强制播放动画。
- 每轮写清修改目的、核验日期与来源、新增/更正/归档数量、未解决线索、实际验证范围。线上检查以生产域真实返回为准，和本地预览分开记录。
